# BDD 测试

完整运行使用仓库根目录的 `make test-bdd`，或在此目录执行 `npm test`。
URL 和凭证可按 Makefile 示例传入，或预先写入忽略的 `runtime/.test-env.json`。
凭证、登录状态、`.env`、报告和截图不能提交。

```sh
# 已配置运行凭证时
make test-bdd

# 聚焦某一文件或模块；仍执行全局 setup/teardown
cd test-bdd/runtime
../node_modules/.bin/playwright test --config=playwright.config.js '02-资源配置/05-'

# 在 test-bdd 目录验证守卫及静态审查指标
npm run test:guard
npm run test:coverage
```

`test:guard` 的三个浏览器探针故意制造未捕获异常、即时 HTTP 500 和延迟 HTTP 500。
验证命令只在三个探针都被守卫判为失败时返回成功；这些本地模拟不能作为站点缺陷证据。
同一命令还验证六个控件正向回归：抽屉、异步下拉、插件可选状态、插件数按钮、异步确认框和仅匹配插件名称。
`test:coverage` 输出文档/脚本映射和弱断言候选，供人工审查，不计算代码或行为覆盖率。
静态声明数不包含参数化展开，应结合 Playwright `--list` 核对实际场景。

## 结果判定

- 每条深链接独立执行，并校验精确路径及目标功能内容。路由通过只说明该入口正常，不代表全部操作通过。
- 所有脚本导入 `runtime/bdd-test.js`。守卫记录未捕获浏览器异常、网络失败和致命 HTTP 响应；结束前等待已经发出的 `/backend/` XHR/fetch 完成，避免漏掉延迟响应。业务测试仍须等待预期请求或状态，守卫不能保证捕获未来定时器尚未发出的请求。
- 断言必须检查操作结果。导入需验证持久化资源，导出需验证下载完成及内容；不能用“按钮存在”代替操作成功。
- 未捕获异常默认使测试失败。场景可用 `test.use({ expectedPageErrors: ['精确校验文字'] })` 声明已确认的预期校验事件；报告保留诊断附件，该场景仍须验证真实业务结果。声明不匹配其他异常，也不豁免失败请求；校验事件不能单独判为功能 bug。
- 缺少外部凭证/测试仓库时必须明确跳过。DeepSeek 全链路需 `TEST_BDD_DEEPSEEK_API_KEY`；没有该凭证时仍可运行模型服务 UI 和参数校验测试。
- setup 前置数据创建失败立即终止。teardown 核对本次网关 ID/名称再删除并回查；清理失败保留归属状态供重试。
- setup 会等待首次资源版本实际发布成功，避免聚焦用例立即再次发布时撞上正在执行的发布任务。
- 共享组件、公开文档和其他网关仅只读。写操作使用本次创建的测试数据；不应将共享申请的审批/撤销/删除作为日常冒烟步骤。

运行报告在 `runtime/reports/<时间戳>/`，包含 JSON、HTML、失败截图和错误上下文。
当前站点的失败 trace 归档可额外超时并产生不完整 zip，默认关闭。
需要诊断时可用 `TEST_BDD_TRACE=1 make test-bdd` 开启；应另行检查 trace 是否完整。
